## 3. 重点観点の確認結果

### 3.1 演算・初期化・jump

| 場所（worktree相対） | 確認結果・根拠 |
| --- | --- |
| `src/core/random.ts:53–68` | scramblerの入力はs1で、1.1の契約と一致。Math.imul、論理右シフトによる回転、最終uint32化、XOR更新順、9bitシフト、11bit回転が同梱著者Cのnextと一致する。符号付き中間値はビット演算の途中に限定され、返却状態はuint32に戻る。 |
| `src/core/random.ts:30,76–94` | 4個のjump定数、各32bitの走査、条件付きXOR累積と毎回のstepがCと一致。最高位bitでAND結果が負でも`!== 0`で正しく判定する。jumpの計算はローカル変数だけを更新する。 |
| `src/core/random.ts:97–119` | 16桁・小文字hexを長さと正規表現で検証。SplitMix64はBigIntによる64bit計算で、加算・各乗算後をmaskする。連続2出力の下位→上位32bitを組み立て、life＝元、flavor＝1 jump、birth＝2 jumpへ割り当てる。 |
| `src/core/random.ts:123–126` | 検証後にu32／2^32のみを返す。状態を受け取らず乱数消費がない。0、1、2^31、最大uint32の固定テストで下端・刻み・上端を確認。 |

著者公開ページも閲覧し、同梱Cの利用部分の式・定数・版を照合した。Web取得は本文照合であり、公開サーバーから取得した生バイト列のSHA-256を再計算したとは扱わない。

### 3.2 状態・消費の分離と入力不変性

`copyRandomState`（38–50行）は入力を検証して4数値の新配列を返す。`step`は分割代入したローカル値から新配列を作り、公開next/jumpは検証コピーを通す。初期化のSplitMix64クロージャは関数内で完結し、返却後の進行状態を隠さない。共有されるモジュール内の進行状態はない。

テストでは各系列に17回の余分な消費を与え、他2系列の状態と後続12出力を比較している。系列間・初期化間・copy/step/jumpでの参照比較に加え、出力側を意図的に変更して入力や他系列に波及しないことも確認している。readonly型だけに依存した検証ではない。

6seedの30回交互呼出し、独立した再実行、11回目の途中状態のJSON往復・コピーからの再開が一致する。frozen入力と呼出し前後の値比較も成功した。これらは今回の乱数APIの再現性であり、未実装のイベント側の消費順や人生全体の再現性ではない。

### 3.3 不正入力

状態操作は配列・長さ4・各要素の数値型／整数／uint32範囲・非全0を検査する。不正値を符号なし化・切捨て・再シードで救済せず、理由付き失敗を返す。

52種類の不正状態をcopy/next/jumpすべてで拒否し、入力と別に保持した正常状態の不変を確認するテストがある。非正規seed20ケース、変換の不正値10ケース、正当な0seed、ゼロワードを含む非全0状態、高位bit・最大値も扱っている。通常の数値配列・JSON由来データに対して、要求された拒否と保持を確認した。独自getter・Proxy等の実行可能な特殊オブジェクトに対する防御まで検証したものではない。

### 3.4 期待値の独立性とテストの検出範囲

`generate-fixture.c`はvendorのSplitMix64とxoshiroをincludeし、nextの名称衝突だけを回避する。初期語順・系列割当てはタスク契約をC側で組み立て、各サンプルを初期状態へ戻して12出力と直後状態を記録する。本番TypeScriptを読み込む経路はない。PowerShellは原本ハッシュ検査、xoshiroのlong-jump手前までの抽出、コンパイル・リンク・JSON保存を行う。通常のVitestは固定JSONを読み、生成・書換えをしない。

本レビューでは同じ抽出境界とCハーネスを使い、別コンパイラGCCで再生成した。6seed×3系列、4直接状態×元/jump/2回jumpの計360遷移を含む生成物は、同梱JSONと完全一致した。

| 誤実装の例 | 検出に対応するテスト・根拠 |
| --- | --- |
| s0/s1の取り違え、遷移順・回転量の誤り | `[1,2,3,4]`を含む直接状態と、出力だけでなく毎回の直後状態の固定比較 |
| 高位bitの符号処理、64bit桁あふれの誤り | 最大値・最高位bit・混合bitのseedと直接状態を含むC固定値 |
| SplitMix64の語順・2出力の順番の誤り | Cの64bit出力hexからの語順確認と、3系列初期状態の固定比較 |
| jump定数・回数・系列割当ての誤り | 元/jump/2回jumpの状態と各後続列、life/flavor/birth初期値の固定比較 |
| 配列共有・入力破壊・余分な消費 | frozen入力、参照比較、出力側変更、系列別追加消費、交互実行・コピー再開 |
| 最大値を1へ変換する分母の誤り | 最大uint32の固定期待値と`< 1`の確認 |
| 不正値の黙った補正 | 不正入力の失敗結果・理由・入力保持の確認 |

上表はテスト内容に基づく検出能力の静的評価である。誤実装を注入するmutation testは行っておらず、あらゆる変異の検出や統計的独立性を証明したものではない。
