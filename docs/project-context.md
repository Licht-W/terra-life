## 2. 仕様の状態と版管理

仕様書第0章の区分を維持する。

| 区分 | 運用上の扱い |
| --- | --- |
| 確定 | 既に合意した方針。変更には本人の採用判断が必要 |
| 採用方針 | P01の設計基準。細部がすべて確定したという意味ではない |
| 提案 | 未採用の具体化。実装に必要な範囲をタスクで採用・委任・保留に分ける |
| 調整値 | 原作事実と区別したゲーム用の値。委任範囲で暫定値を置き、記録して試遊で見直す |
| 保留 | 必要になる工程まで保留。先回りして実装しない |

仕様書の第15章・付録は、小さな技術判断や調整値を記録して進める方針を含む。作成当初の依頼は運用文書作成のみ、その後のTL-M0-001・TL-M1-001の限定実装は受入れ済み。今回のTL-M1-002は出生だけに限定し、候補・重み・固定シード等の検証値をD09の範囲で委任する。値・理由・見直し条件は同タスク末尾に記録し、ゲーム用バランスへ昇格させない。M1設計の採用済み範囲は設計書第11〜14章を参照し、全提案・全検証候補を自動採用しない。

ゲーム仕様の版は、新しい開発段階の初期案で中位を1増やす（例：v0.3.2→v0.4.0）、同段階の修正では末尾を1増やす（例：v0.3.1→v0.3.2）。ファイル名・本文見出し・参照名を一致させる。運用文書版・タスクID・コードcommitは別に管理する。M0→M1という工程移行だけで仕様版を自動更新しない。
